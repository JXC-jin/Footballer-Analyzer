# 从跟踪轨迹到足球统计指标：算法与坑（调研报告）

> 所有数字均来自下列链接的公开来源；未能核实的一律标注「未核实」。

## ① 结论速览

**能直接从轨迹算**：跑动距离（总距离很稳、分速度区间不稳）、速度/加减速、控球时间占比（口径自定）、传球/触球的**估计**（已可仅用球员轨迹）、pitch control / Voronoi 空间控制、阵型形态。

**必须有事件数据（或先做事件检测）**：xG、xT、VAEP、PPDA、传球成功率的标准口径、解围/争顶等离散动作。

**误差来源排序（大→小）**
1. **身份跳变 / 换人 / 遮挡**（track ID switch）：把两人轨迹拼成一条，误差随跳变次数累积，属「量级」级错误，而非几个百分点。
2. **标定**：单应性残差（远端、边线、鱼眼畸变）。
3. **跟踪缺口与插补**。
4. **低速段距离**：TRACAB Gen4 vs VICON 在低速区间距离偏差 **−19.41 ± 13.24%**、高速区间 **+8.94 ± 9.49%**，而**总距离仅 0.42 ± 0.60%**；位置 RMSE 0.08–0.09 m、瞬时速度 RMSE 0.08–0.09 m/s、加速度 RMSE 0.21–0.26 m/s²（已剔除明显未跟踪帧）——[Linke et al., PLOS ONE 2020](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0230179)。
5. **语义口径**：什么叫控球、什么叫传球成功。

> 注意 4 的前提是**专业球场多相机系统 + VICON 参考**。单目/鱼眼/手机的精度远不及，见 [SoccerTrack, CVPRW 2022](https://openaccess.thecvf.com/content/CVPR2022W/CVSports/html/Scott_SoccerTrack_A_Dataset_and_Tracking_Algorithm_for_Soccer_With_Fish-Eye_CVPRW_2022_paper.html)。

## ② 各指标算法

### 1. 坐标变换与滤波
- **单应性**：球场关键点检测 → `findHomography` → 米制；工具与关键点数据集见 [roboflow/sports](https://github.com/roboflow/sports)。SoccerNet 2023 单设 camera calibration 任务恢复相机内外参（[arXiv:2309.06006](https://arxiv.org/abs/2309.06006)）。
- **滤波三选一**
  - **One-Euro**：低速强平滑、高速低延迟，正合「距离怕抖、冲刺怕延迟」。Casiez, Roussel & Vogel, CHI 2012（[DOI](https://dl.acm.org/doi/10.1145/2207676.2208639)），官方实现 Python(BSD)/C(MIT)：[casiez/OneEuroFilter](https://github.com/casiez/OneEuroFilter)。调参：β=0、f_cmin≈1 Hz 先压抖动，再快速移动调 β（0.001/0.0001 量级起）。
  - **Savitzky-Golay**：滑窗多项式最小二乘，适合离线整段（零相位）；奇数窗长 + 阶数，窗长随采样率缩放。
  - **Kalman**：可在线，但需建模过程/观测噪声；恒速模型会平滑掉真实加减速。
- **采样率与噪声敏感性**：对位置一阶差分求速度，v=Δx/Δt，独立噪声下方差放大为 2σ²/Δt²（速度噪声 ∝ 1/Δt）→ **必须先滤波再差分**；加速度再差一次，对噪声最敏感（上表 RMSE 最大）。
- **跑动距离标准做法**：按 track ID 分段 → 逐帧位移求和 → 输出总距离**同时**分速度区间；对短于 0.2–0.5 s 的方向抖动做去抖，但必须显式声明低速区间不可信。
- **缺口/身份**：SoccerNet 2023 专设 re-identification 与 MOT 任务；轨迹插补对统计量的影响见 [arXiv:2408.10878](https://arxiv.org/abs/2408.10878)（具体数字未核实）。

### 2. 控球（possession）
- **启发式（几行代码）**：逐帧取最小球-人距离；属队 A 则 A 控球；加**滞后**（进入阈值 < 退出阈值）+**最短持续时间**去抖；球速超阈或离所有人过远 → 无控球（球在飞行）。
- **轨迹法（更稳）**：[PathCRF, KDD 2026 / arXiv:2602.12080](https://arxiv.org/abs/2602.12080) **不用球轨迹**：球员轨迹建成动态完全图，每帧选一条边表示当前控球人，CRF 禁止非法转移，Viterbi 解码；边切换即触球/传球。代码 [hyunsungkim-ds/pathcrf](https://github.com/hyunsungkim-ds/pathcrf)。
- **定义差异**：StatsBomb 等事件流的 possession 是**事件分段**（possession 编号 + 归属队，见 [StatsBomb 规范](https://raw.githubusercontent.com/statsbomb/open-data/master/doc/StatsBomb%20Open%20Data%20Specification%20v1.1.pdf)），与逐帧控球状态不是同一对象。
- **控球率两种口径**：**控球时间占比**（轨迹天然）vs **触球/事件次数占比**（事件流天然）。数值可差数个百分点，输出时必须写清是哪种。

### 3. 传球（pass）
- **链路**：触球检测 → 球权转移/控球人切换 → 出球方向与接球人（最近队友 vs 球轨迹外推交点）→ 事件属性。轨迹侧实现见上条 PathCRF。
- **传球成功率口径**先定：分母是否含**被断**、**出界**、**二点球**、传中/角球/解围；可用 [socceraction/SPADL](https://github.com/ML-KULeuven/socceraction) 的 action outcome 作统一模板。
- **对齐率**：SoccerNet action spotting 是**转播视频**上的时间戳任务，不能直接当轨迹传球检测的基准（见 5）。事件-轨迹同步的公开工作见 [ELASTIC, MLSA 2025](https://arxiv.org/abs/2508.09238)（标注 3 场 Eredivisie 共 2134 事件作 ground truth，精度数字未核实）。

### 4. 进阶指标
- **xT**：Karun Singh [博客](https://karun.in/blog/expected-threat.html)，需事件流起终点坐标 → 纯轨迹不行。
- **VAEP**：Decroos et al., KDD 2019；[socceraction](https://github.com/ML-KULeuven/socceraction)（**MIT**）提供 SPADL/atomic-SPADL + VAEP + xT，输入为 StatsBomb/Opta/Wyscout/Stats Perform/WhoScored 事件流。README 自述**已不活跃开发**、定位是复现研究 → 不宜作生产依赖。
- **EPV**：Fernández, Bornn & Cervone [arXiv:2011.09426](https://arxiv.org/abs/2011.09426)，**从 low-level spatiotemporal（跟踪）数据**学习概率面 —— 这是「纯轨迹可算控球价值」的主要依据。但 [Overmeer et al. 2025, arXiv:2502.02565](https://arxiv.org/abs/2502.02565) 明确称**复现该结果失败**，并提出首个 EPV benchmark（其新模型在 78% 的成对状态上判对）→ 不要期待开箱复现。
- **务实路径**：先用路径 2/3 从轨迹生成事件，再接 VAEP/xT。

### 5. 事件 spotting（SoccerNet）
- **任务**：在长未剪辑转播视频中检索动作的**单时间戳**（进球=球过门线那刻，角球=踢球那刻）；500 场 / 17 类 / 110,458 动作 + 50 场隔离标注（[arXiv:2210.02365](https://ar5iv.labs.arxiv.org/html/2210.02365)）。
- **指标**：Average-mAP = 不同容差 δ 下 mAP 的 AUC；**loose δ=5–60 s，tight δ=1–5 s**。2022 年 tight 从 49.56 提升到 **67.81**（Yahoo Research；loose 78.05；visible 72.84 / unshown 60.17）。2023 扩为 7 任务。代表方法：NetVLAD++、E2E-Spot、ASTRA、Soccer-CLIP、[arXiv:2404.09951](https://arxiv.org/abs/2404.09951)。**当期 SOTA 未核实**（以 soccer-net.org 榜单为准）。
- **对自有摄像头系统的适用性：低**。标注与预训练绑定转播语言（多机位、回放、字幕板、导播切换），动作时间常源自回放；且输出只有时间戳、没有「谁传给谁」。自采固定机位/鱼眼/无人机应参考 SoccerTrack 与 SoccerNet-Tracking（12 场单主摄像机整场），而非 spotting 榜单。

### 6. 阵型与战术
- **Pitch control**（Spearman 模型）与 EPV 传球评估：[LaurieOnTracking](https://github.com/Friends-of-Tracking-Data-FoTD/LaurieOnTracking) Tutorial 3/4，输入=轨迹，**可直接算**；Voronoi 是它的简化替代。
- **阵型识别**：轨迹按线/块聚类 → 阵型编号；LaurieOnTracking 亦含阵型测量代码（具体算法与精度未核实）。
- **PPDA** 是事件计数型指标，纯轨迹需先检测传球与防守动作 → 归入「先别做」。

## ④ 实现优先级建议

**先做（最稳 3 个）**
1. **总跑动距离 + 速度剖面**：算法最短、口径可自证；但必须先解决 ID 跳变，并同时输出「低速区间不可信」提示。
2. **控球时间占比**：球-人距离 + 滞后 + 最短时长即可；把口径写进报告，避免与转播口径对不上。
3. **Pitch control / 空间控制 + 位置热图**：纯轨迹、可视化价值高、不依赖外部真值。

**其次**：阵型识别、传球**估计**（PathCRF 类）、压迫几何量。

**先别做**：xG、xT、VAEP（需事件流，且 EPV 复现性被公开质疑）、传球成功率（依赖事件检测精度）、PPDA、SoccerNet action spotting（依赖转播视频与回放）。
