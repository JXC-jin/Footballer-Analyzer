# 04 · 主干选型决策（效率优先）

> **决策原则**：**效率优先**（用户 2026-10-15 指定）—— 在"精度可用"前提下选实现成本最低的路径；许可协议不构成约束（黑客松项目）。
> **状态**：D0–D13 十四个决策点**已全部定稿**。设计阶段（架构 / 数据模型 / 接口 / 排期）尚未开始。

---

## 一、决策总表

| # | 决策点 | ✅ 决定 | 效率优先的理由 | 未选用 |
|---|---|---|---|---|
| **D0** | 许可定位 | **不设限**，直接用最省事组件；检测器/跟踪器包成可替换接口 | 黑客松，跑通优先 | 全程 MIT/Apache 约束 |
| **D1** | 检测器 | **YOLOv8n + COCO 预训练权重（零训练）** | 实测直接可用：素材上平均 16.4 person/帧、框高 100% ≥30px，**省掉训练环节** | RT-DETR / YOLOX / 足球微调权重 |
| **D2** | 球检测 | **推迟到有余量再做**；届时用独立小模型 + 切片推理 | COCO `sports ball` 在测试素材上 **0/125 帧**命中 → 零训练路径不成立；且球是补充项 | 一个模型多类别 / 零样本检测 |
| **D3** | 跟踪 | **supervision `ByteTrack`** | 零成本，几十行接上 | boxmot / 自写 OC-SORT / Deep-EIoU |
| **D4** | ReID | **不做自动 ReID**；人工初始化 + 跟踪连续性 | 德甲式人工初始化已替代身份识别，直接砍掉最难的模块 | OSNet / PRTReID |
| **D5** | 分队 | **HSV 球衣主色 + KMeans(2)**；SigLIP 备用 | 无模型下载、启动快、结果可解释；测试素材两队颜色分明 | SigLIP+UMAP+KMeans（需下 HF 权重） |
| **D6** | 标定 | **手工点关键点 → `findHomography`（单一 H）** | 固定机位只需标一次，避开动态单应的开发量 | 球场关键点模型逐帧单应 / PnLCalib |
| **D7** | 坐标/存储 | **米制 105×68 + Parquet** | 列式、pandas 直接读、体积小 | 厘米制 / CSV / SQLite |
| **D8** | 推理后端 | **PyTorch CPU** | 实测 26.7 ms/帧，5 秒片段 3.4 秒跑完，**无需优化** | ONNX+DirectML（留作加速层） |
| **D9** | 解码/抽帧 | **OpenCV + `vid_stride` 可配** | 依赖最少 | PyAV / ffmpeg 管道 |
| **D10** | 评估 | **可视化对拍** | 没有标注真值，算 HOTA 既无意义又费时 | sn-trackeval / SportsMOT |
| **D11** | 指标 | **跑动距离 → 速度/热图 → 控球率**（按用户三层优先级） | 前两层不依赖球，风险最低 | 传球 / 阵型 / pitch control |
| **D12** | 工程形态 | **Python 包 + CLI + YAML 配置** | 5 天内够用，且团队可读 | 单体脚本 / 服务化 |
| **D13** | 素材 | **用现有片段裁剪**（见第三节） | 免申请、免拍摄，**立刻可开工** | SoccerTrack v2 / SoccerNet / 自拍 |

## 二、支撑这些决策的实测证据

| 证据 | 数值 | 影响 |
|---|---|---|
| COCO YOLOv8n 检出球员 | 平均 **16.4 person/帧**（10–22），框高中位 63 px、最小 32 px，**100% ≥30 px** | 支撑 D1：检测器零训练即可用 |
| COCO 检测球 | **0/125 帧** | 支撑 D2：球必须专门处理，零训练路径不成立 |
| 检测单帧耗时 | 26.7 ms（PyTorch CPU, imgsz 640） | 支撑 D8：无需推理优化 |
| 镜头运动（goodview 全片 30 s） | 累积漂移 **621 px** | 转播素材不能用单一 H 标定 |
| 镜头运动（goodview 第 175–300 帧） | 累积漂移仅 **6.5 px** | 支撑 D6：存在可用的"准固定机位"窗口 |

## 四、仍需处理的约束

1. **球**：零训练路径不成立，需专门模型与切片推理；按需求 Q7 属可选项，不进关键路径。
2. **镜头运动**：现有素材是转播片段、镜头持续移动，标定/测距**只在静止窗口成立**。因最终产品为固定机位，**不为此开发动态单应**；若需长时间测距验证，可对片段做平移稳定化，或改拍一段固定机位素材。
3. **目标机位素材仍缺**：`goodview` 的机位比参考图高（像素密度好得多），但并非最终机位。建议后续补一段真实机位录像复核（不影响现在开工）。
