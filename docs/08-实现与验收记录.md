## 一、已交付能力

| 环节 | 实现 | 操作入口 |
|---|---|---|
| 跟踪缓存 | YOLOv8n COCO person、CPU 推理、ByteTrack、上衣 HSV/KMeans(2)、原始轨迹 Parquet | `track --config configs/demo.yaml` |
| 同帧对拍 | 源视频 JPEG、检测框和脚点、SVG 球场、轨迹联动选择、逐帧/播放/源帧跳转 | `serve --port 8765` 后打开浏览器 |
| 标定 | 对应点、实际尺寸、可靠地面多边形、参考帧与适用窗口、白线反投影 | 前端“场地标定”，或 `calibrate --run ... --points ...` |
| 人工身份 | 持久档案、区间绑定、排除、冲突检查 | 前端“身份与轨迹”或编辑 YAML |
| 报告 | 投影、无效点/缺口/绑定边界切段、One-Euro 滤波、距离/速度/覆盖/热图 | 前端“跑动统计”，或 `report --run ...` |
| 版本与历史 | 报告输入快照、修改后过期提示、同秒报告按完成时间选择、显式选择历史版本并防重复 | `history --player ... --reports ...` |
| 复查产物 | 静态 HTML、叠加视频、统计表、当前画面与球场并排 PNG | 完整报告链接；“导出对拍图”→“保存 PNG” |

实现保持两阶段边界：跟踪完成后编辑身份或标定，只重算报告，原始 `tracks.parquet` 不变。逐帧轨迹分批写入；当前报告和浏览器接口会载入所选运行的全部轨迹，不声称已支持整场的大规模内存负载。

## 三、报告与纠错验收

### 自动化测试

```powershell
& .\.venv\Scripts\python.exe -m unittest discover -s tests -v
node --check src/footballer_analyzer/web/app.js
git diff --check
```

当前 **11 项 unittest 全部通过**，同时通过 JavaScript 语法检查和补丁空白检查。

| 测试 | 验证内容 |
|---|---|
| `test_video.py` | 实际生成并解码短视频；stride 保留源帧号、真实时间与对应像素 |
| `test_metrics.py`（5 项） | 缺失不跨段连接、同 ID 换身份切段、断轨绑定同一身份不跨缺口计距、未绑定/异常跳变不计距、重叠身份拒绝 |
| `test_reporting.py`（4 项） | 完整生成 Parquet/HTML/图表/可解码视频；汇总与逐点一致；重算保留旧版本和原始轨迹摘要；身份变更更新统计并切断边界；同秒逆序 ID 仍选最新完成报告；重复历史、草稿和共线点拒绝 |
| `test_server.py` | 启动真实本地 HTTP 服务；运行列表、源帧 JPEG；越界帧、路径、跨来源写入、错误 Host 拒绝 |

报告测试使用临时生成的 64×48、25 FPS、10 帧 AVI 与已知单应性，不运行检测模型，不依赖第三方视频。身份纠错先生成一版，再把同一轨迹在第 5 帧拆成两名球员，重算后两人各有 0.16 秒有效时间，切换点无位移/速度，原始轨迹摘要保持一致。

### 浏览器集成检查

本机另保留 `outputs/run_00000000_synthetic_smoke/`（列表显示 `synthetic_smoke_test`），使用同一测试夹具构造，源文件在 `outputs/smoke_fixture/`。这是**合成测试运行**，不能当真实比赛。

已从浏览器点击“生成 / 重算报告”，确认统计行、完整报告链接、速度/热图图片加载成功。该夹具显示约 0.06 m、0.36 s、90% 窗口覆盖；这些只是合成输入经过滤波后的链路结果。浏览器日志未出现错误。

对拍 PNG 已验证在页面生成，内容可解码、尺寸 1600×760。内置浏览器自动化未捕获到下载事件，因此验收图通过读取页面已生成的 PNG 数据保存到本地；普通浏览器的下载落盘仍需用户实际点击验证。

## 四、运行与接口

完整安装与操作见根目录 [README](../README.md)。CLI 使用 Python 包方式启动，默认仅监听 `127.0.0.1:8765`。前端为包内静态文件，无 npm 安装和构建要求。

| 本地 API | 用途 |
|---|---|
| `GET /api/runs` | 可用运行和状态 |
| `GET /api/runs/{run_id}` | 原始观测、档案、绑定、标定、报告及过期状态 |
| `GET /api/runs/{run_id}/frames/{frame_index}` | 指定源帧 JPEG |
| `POST /api/runs/{run_id}/players` | 保存球员 ID 与显示名 |
| `POST /api/runs/{run_id}/bindings` | 校验并保存整份区间映射 |
| `POST /api/runs/{run_id}/calibration` | 校验几何、窗口与确认状态，保存标定 |
| `POST /api/runs/{run_id}/report` | 同步生成新报告版本 |

小规模本地复盘使用同步报告接口，生成时暂停预览。没有对外部署、任务队列、远程登录与多用户并发编辑能力。换视频请复制配置并填写独立 `match_id/clip_id`，不要把旧 `run_id` 的绑定直接用于新检测结果。

## 五、实际依赖与复现范围

Windows x64、Python **3.12.10**；CPU PyTorch **2.14.1+cpu**、torchvision **0.29.1+cpu**。其他直接依赖的验证版本在 `configs/constraints-tested.txt`，包括 Ultralytics 8.4.177、supervision 0.27.0.post2、OpenCV 5.0.0.93、numpy 2.5.2、pyarrow 26.0.0、scikit-learn 1.9.1、SciPy 1.18.1、PyYAML 6.0.3、matplotlib 3.11.2。

该文件是本轮直接依赖的版本约束，不是完整跨平台锁文件。PyTorch 通过官方 CPU 索引单独安装；`pyproject.toml` 限定 supervision `<0.28` 以保留当前 ByteTrack 接口。Node 仅用于可选的 JavaScript 语法检查，运行前端无需 Node。
